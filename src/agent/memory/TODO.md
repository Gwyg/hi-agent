# 记忆层问题记录与待办

> 本文档是记忆层的跨会话待办清单,供接手者/后续开发参考。
> 当前问题:长任务(单轮多工具)执行中 agent"读着读着忘了原始指令"。

## 问题现象

- 用户让 agent 分析项目并生成 AGENT.md,agent 读了 26 个文件后,
  反而回复"你好,请问需要我帮你做什么?"——原始任务指令丢失。
- 追问"帮我生成这个文件呀"后,agent 反问"哪个文件?",连任务产物名也不记得。
- 根因不在模型,在记忆层:任务指令进了滚动窗口,滚动窗口被截断时指令被连锅端。

## 根因分析

### 1. hard_truncate 边界 bug(最直接,必修)

`working/mod.rs::hard_truncate`:
- 总量超 `MAX_CHARS = 120_000` 字符即触发;
- 从尾部累计找 `cut`,再向后找**下一个 user 边界**对齐;
- 但单轮多工具场景下消息列表只有**一个 user**(最初的任务指令),
  `cut` 之后没有 user,`new_start` 扫到 `msgs.len()`,`drain(0..len)` 全删。
- 结果:下一轮模型只剩 system,无摘要无历史,像新会话。

### 2. 压缩在长任务场景永不触发

`working/compact.rs::compact_boundary`:
- 要求 `users.len() > COMPACT_TURNS(6)` 才压缩;
- 单轮多工具(26 个 read)时 user 只有 1 个 → 返回 None;
- 精心实现的摘要器(`SUMMARY_SYS` 保留目标/待办/决策/风险)在长任务场景是死代码。

### 3. 任务指令未钉在受保护层

- `core.rs` 的 Core 层只存 system prompt,不存用户任务;
- 成熟方案(Claude Code / opencode)把任务/指令常驻 system,
  滚动窗口只删工具噪音,压缩时摘要器被要求保留用户原始目标。

### 4. 读取量无硬限制,上下文提前爆炸(放大器)

- `read` 不传 limit 时整读小文件,26 个文件内容全量进上下文;
- 成熟 agent:read 强制 2000 行分块 + 代码索引让模型"挑着读",
  上下文里根本不会出现 26 个整文件。

## 修复待办

按优先级排序:

- [ ] **P0 修 hard_truncate 边界 bug**:找不到 user 对齐边界时,
      保留第一条 user 消息(任务指令),只截中间的 tool 结果,绝不全删。
- [ ] **P1 压缩改水位触发**:不再卡 `users.len() > COMPACT_TURNS`,
      按 token 水位触发,无条件压最老 chunk,任务意图留在摘要"目标"段。
- [ ] **P1 Core 层持久化当前任务**:Core 增加 task 段,用户当前请求常驻 system,
      不随滚动窗口删除。
- [ ] **P2 read 默认限行**:`read` 不传 limit 时默认 `limit=2000`,
      模型要更多必须显式分页(防上下文爆炸的放大器)。
